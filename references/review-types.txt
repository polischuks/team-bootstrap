# review-types.txt — the SINGLE SOURCE OF TRUTH for "which subagent_type counts as an independent
# review dispatch" (milestone exec-role-integrity, v2.21.0). One slug per line; blank lines and
# lines beginning with '#' are ignored; matching is exact (anchored, whole-slug).
#
# Read by (and ONLY by) delivery-lib.sh review_types()/is_review_type(), which back:
#   - bin/record-dispatch.sh   — the non-blocking PreToolUse[Agent] recorder
#   - bin/check-role-dispatch.sh — the verify-batch role-dispatch gate
#   - references/subagent-dispatch.md / subagent-mapping.md — the doctrine the reviewers dispatch by
# Keeping the set here (not duplicated in each script) is soundness fix N3: the doctrine, the
# recorder, and the gate cannot drift apart.
#
# HONEST LIMIT (ADR-0008): subagent_type is the model's dispatch ARGUMENT, not a harness-minted value.
# So this signal is DEGRADATION-proof (an orchestrator that collapses review to inline dispatches NO
# review-typed subagent — the spec-169 failure — is caught) but NOT forgery-proof (a decoy review-typed
# no-op dispatch would satisfy it — the ADR-0006 quality/willingness limit). It proves a reviewer was
# DISPATCHED and independent (≠ builder type), not that the review was good.
#
# WHAT dispatch.jsonl IS, AND WHAT MAY NOT BE CONCLUDED FROM IT (spec 021 D2, AC-4/AC-5, ADR-0023).
# bin/record-dispatch.sh appends one line per review-typed dispatch:
#     {"batch":"<id>","subagent_type":"<slug>","outcome":"attempted"}
# `outcome` is always the literal `attempted`, and there is no other value. The recorder is a
# PreToolUse hook: it fires BEFORE the tool executes and returns before the outcome exists, so an
# ATTEMPT is the entirety of what it can witness. The field carries that in the record rather than
# leaving it to this file, because a reader holding one line must be able to see what the line is
# worth without opening a second one.
#
# MAY be concluded: a review-typed, builder-independent invocation was requested for that batch. That
# is the anti-collapse floor (check-role-dispatch's >=1, the per-role floor, reviewer_dispatch_count)
# and it is exactly what defeats the spec-169 collapse, where NO review-typed dispatch is requested.
#
# MAY NOT be concluded: that the subagent launched, ran, finished, or returned anything; that a review
# HAPPENED; that a required role is satisfied. Confirmation of a review is a typed verdict recorded by
# check-role-verdict from the finished subagent, and nothing else stands in for it. A gate that reads
# completion out of this file is reading a claim the file never makes.
#
# BACK-COMPATIBILITY: `outcome` is additive and no consumer may REQUIRE it. Records written before
# v3.3.0 have no such field and still count toward every floor above; requiring it would empty a
# long-lived ledger of its own history the day the field appeared.
#
# Membership + the OPTIONAL role column (all-four-role-dispatch, v2.22.0): a line is `slug` OR
# `slug<TAB>role`. Column 1 (the slug) is what is RECORDED (is_review_type); an optional TAB-separated
# column 2 is the ATTRIBUTED role (role_of_slug), read by the per-role floor. Only the four dedicated
# slugs below carry a role and attribute; the generics carry no role — they satisfy the legacy ≥1
# total-collapse floor but do NOT attribute to a specific role.
#
# MANDATE (supersedes exec-role-integrity's "independent-reviewer for all four" — ADR-0008 → the
# all-four-role-dispatch ADR): each of the FOUR mandatory review roles dispatches under its OWN dedicated
# type — integration-verifier / architecture-reviewer / regression-guardian / tb-code-reviewer — because
# `subagent_type` alone could not otherwise attribute a dispatch to a role (integration-verifier and
# regression-guardian shared byte-identical preferred types; independent-reviewer was shared by all four).
# The bare `independent-reviewer` and host review slugs remain honored for the ≥1 floor during the
# warn→enforce ramp (the gate defaults to WARN until references/role-dispatch-enforce is committed, after
# the dispatch probe confirms four-distinct-slug adoption). Each dedicated slug is listed in BOTH forms
# (team-bootstrap:<slug> AND bare <slug>) because the team-bootstrap: prefix is not reliably delivered in
# subagent_type; the code-review slug is `tb-code-reviewer`, NOT bare `code-reviewer`, to stay attributable
# even when bare. Load-bearing guarantee is anti-builder: NO builder role maps to any slug here.
#
# HONEST LIMIT carried forward: per-role raises the DEGRADATION floor (a partial 1-of-4 collapse is now
# caught under enforce), NOT the FORGERY bar — four decoy no-op dispatches under the four dedicated types
# still satisfy it (ADR-0006/0008 quality-willingness limit). Dispatch ≠ completion (check-review-ack).
